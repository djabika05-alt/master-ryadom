# МАСТЕР РЯДОМ — веб-приложение, MVP v1

Рабочий прототип сайта с Node.js сервером, русским интерфейсом и хранением данных в `data.json`.

## Запуск

Требуется Node.js 18+. Команда: `npm start`. Открыть http://localhost:3000.

Для размещения в интернете нужен хостинг Node.js с **постоянным диском**. Установите `PORT` по требованиям хостинга. HTTPS необходим для безопасной работы в интернете.

## Реализовано

- Регистрация и вход заказчика или мастера по телефону и паролю (без SMS подтверждения)
- Создание заявок и просмотр списка заказов
- Отклики мастеров с ценой и комментарием
- Выбор мастера заказчиком
- Переписка между заказчиком и выбранным мастером
- Завершение работы и отзыв
- Адаптивный интерфейс для Android и других телефонов

## Важно перед публичным запуском

Это **MVP для тестирования**, не production. Для реального публичного запуска необходимо заменить JSON-хранилище на БД с транзакциями, добавить резервные копии, SMS-верификацию, восстановление пароля, защиту от перебора и спама, rate limiting, модерацию, правовые документы и политику обработки персональных данных. Телефон пользователей не показывается в открытых карточках. Фото и геолокация пока не реализованы. Чат обновляется при повторном открытии, не в реальном времени. Встроенной оплаты нет.

Данные хранятся локально в data.json, поэтому при запуске на эфемерном хостинге могут исчезнуть. Не используйте реальные персональные данные при тестировании.

## Обновление безопасности (20.10.2026)
- У новых пользователей индивидуальная соль пароля; старые тестовые аккаунты совместимы с прежним хешем.
- Ограничение попыток входа (базовое, в памяти процесса), безопасное сравнение хешей.
- Атомарное сохранение JSON-файла, защита от обхода пути и базовые HTTP-заголовки.
- **Важно:** Это всё ещё тестовая версия. JSON-файл не подходит для нескольких серверов или эфемерного хостинга; нет SMS-подтверждения, HTTPS на самом сервере, восстановления пароля, полноценной защиты от злоупотреблений и резервного копирования. Не запускать публично с реальными персональными данными.

## Версия 3 — автоматические проверки

Запуск: `node tests/smoke.mjs` (Node.js 18+). Тест поднимает временный сервер, создаёт два тестовых аккаунта, проводит заявку через полный цикл, проверяет права доступа и удаляет тестовые данные. 14 проверок успешно пройдены на Node.js 22.

Исправлено: внутренние идентификаторы заказчика и исполнителя скрыты в публичном списке заявок; усилена проверка полей регистрации, заявки и цены отклика. Для публичной эксплуатации всё ещё требуются постоянная БД, SMS/подтверждение контактов, антиспам, юридические документы и хостинг с HTTPS.

## Версия 4 — SQLite и подготовка контейнера

- Требуется **Node.js 22.13+** (используется встроенный модуль `node:sqlite`).
- Данные сохраняются в `master-ryadom.sqlite` либо по пути `DB_PATH`.
- При первом запуске существующий `data.json` импортируется в SQLite, если база ещё пустая. После миграции исходный JSON следует хранить только как резервную копию.
- Добавлены `Dockerfile`, `.dockerignore`, `.gitignore`.
- Проверка: `npm test` — 14 автоматических проверок.
- **Важно:** SQLite требует постоянного диска/тома на хостинге. При запуске Docker подключите постоянный том к директории базы и задайте `DB_PATH` (например, `/data/master-ryadom.sqlite`). Без тома данные могут пропасть при пересоздании контейнера.
- Это пока тестовый MVP: отсутствуют SMS-подтверждение телефона, восстановление доступа, продвинутый антиспам, модерация, резервные копии и необходимые правовые документы. Не вводите настоящие персональные данные при тестировании.

## Версия 5 — подготовка к размещению

- Добавлена проверка работоспособности `GET /api/health` для хостинга.
- Docker запускается от непривилегированного пользователя `node`; путь базы `/data/master-ryadom.sqlite`.
- `compose.yaml` сохраняет базу в именованном томе `app_data`. Порт доступен только локально на сервере, для внешнего доступа нужен HTTPS reverse proxy.
- Локальная проверка: `npm test`. Docker: `docker compose up -d --build`.
- **Это не опубликованный сайт.** Для доступа по ссылке нужен сервер/хостинг с HTTPS и постоянным диском. Перед настоящим запуском обязательны усиление защиты, резервные копии, правовые документы и тестирование.

## Версия 6 — управление сессиями и ограничения

- Сессии входа действуют 7 дней, затем требуется повторный вход. Старые тестовые сессии без времени создания перестают действовать.
- Ограничена частота регистрации с одного IP (в памяти сервера; для публичного запуска нужна общая система ограничений и учёт доверенного прокси).
- Добавлены дополнительные HTTP-заголовки безопасности.
- Для публичного запуска по-прежнему необходимы HTTPS, постоянный диск, резервное копирование, проверка телефона, модерация и юридические документы.
