# Фото, видео и портфолио

Реализовано в ветке `feature/media-portfolio` на основе `test-notifications`.

## Поведение

- Заявка: до 10 фото и 2 видео; можно просмотреть и убрать файлы перед публикацией.
- Переписка после выбора мастера: до 10 фото и 2 видео на сообщение, в том числе без текста. Вложения доступны только участникам чата.
- Кабинет мастера: до 50 работ, у каждой название, описание, до 10 фото и 2 видео. Работа публична; есть отдельная ссылка на портфолио и переход из отклика мастера. Владелец может удалить работу с её файлами.
- Фото: JPG, PNG, WebP, до 15 МиБ. Видео: MP4, MOV, WebM, до 50 МиБ. Проигрывание зависит от поддержки кодека браузером; транскодирования нет. Видео скачивается после нажатия, затем проигрывается из локального blob URL.
- Общий лимит: 500 МиБ на пользователя. Тип файла проверяется на сервере по сигнатуре; SVG/HTML не принимаются. Принимаются неиспользованные вложения только самого отправителя с соответствующим назначением.
- Фото открытых заявок и опубликованного портфолио публичны; черновики приватны. После назначения мастера фото заявки доступны её участникам.

## Перед включением на Render

Существующий бесплатный сервис использует локальный SQLite. Не сливать эту ветку в автоматически развёртываемую ветку, пока постоянное хранилище не подготовлено и вопрос переноса существующих данных не решён. Любое новое развёртывание текущего бесплатного сервиса может потерять старую локальную базу.

1. Подготовить приватный S3-совместимый bucket. Аккаунт/квоты/оплата провайдера согласуются отдельно. Код не создаёт платных ресурсов.
2. Создать отдельный префикс для тестового сервиса. Основной и тестовый сервисы не должны использовать один префикс.
3. В безопасных настройках Render задать переменные из `.env.example`. Не отправлять секретные ключи в переписку или GitHub.
4. Разрешить ключу только операции GetObject, PutObject, DeleteObject в этом префиксе. Публичный доступ к bucket запретить. Все файлы приложение отдаёт через свои проверки доступа; CORS на bucket для браузера не нужен.
5. Если есть прежние данные, сначала получить их резервную копию. Для переноса загрузить JSON payload из таблицы SQLite `app_state` как `<S3_PREFIX>/state.json` с типом `application/json`. Пустое хранилище начинает с пустой базы; автоматического восстановления старых записей нет.
6. Слить проверенную ветку в `test-notifications`, дождаться успешного развёртывания; проверить регистрацию, заявку с фото/видео, чат между двумя аккаунтами и публичное портфолио. Перезапустить тестовый сервис и проверить сохранность.

В режиме `MEDIA_STORAGE=s3` база (пользователи, заявки, сессии, переписка и метаданные файлов) также хранится в приватном bucket. При сбое облака нет незаметного переключения на временную локальную базу. Условная запись по ETag предотвращает молчаливое перетирание данных другим процессом. Конфликт возвращается как ошибка, его можно повторить после обновления.

Это небольшой однопроцессный MVP: состояние хранится одним JSON-объектом; запросы последовательны. Для роста нагрузки нужна отдельная транзакционная база и прямая загрузка в объектное хранилище. Секреты и хеши паролей в объекте состояния требуют строгого ограничения доступа и резервного копирования/версионирования bucket. Резервное копирование провайдером этим кодом не включается.

## Локальная проверка

```bash
npm ci
npm test
MEDIA_STORAGE=local DB_PATH=./var/state.sqlite MEDIA_DIR=./var/media npm start
```

`npm test` использует временные каталоги и локальный тестовый S3 HTTP-сервер, не обращается к действующему сайту. Проверяет доступ к вложениям, лимиты, уведомления/переписку, портфолио и сохранность после замены локального диска. Это не заменяет проверку конкретного реального S3-провайдера.

Без `MEDIA_STORAGE` новые загрузки отключены с понятным сообщением; существующие текстовые сценарии сохраняются. `MEDIA_STORAGE=local` запрещён в окружении Render.
